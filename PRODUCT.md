# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Existing static HTML/CSS/vanilla JavaScript site; no build step. GitHub Pages is the intended publishing target.

## Users

Primary audience is inferred from the portfolio context: recruiters, hiring managers, collaborators, and technical peers evaluating Lintao (Andy) Zhang's work.

## Product Purpose

Present Lintao's software, data, AI, research, IT, and operations experience in a concise portfolio that helps a visitor understand his strengths, inspect real projects, open the live AI Customer Support demo, view source code, download the resume, and make contact.

## Positioning

The portfolio connects software and data work with practical business and operations experience, rather than presenting isolated technologies without context.

## Operating Context

Visitors may scan the page quickly on desktop or mobile, then follow project links, inspect the AI Customer Support live demo, open GitHub repositories, or download the resume. The site should remain fast, readable, keyboard-accessible, and understandable without requiring a long interaction.

## Capabilities and Constraints

- Preserve the existing factual portfolio content unless the user provides a correction.
- Keep the site deployable as a static website without introducing a framework migration or backend.
- Use real project links and supplied screenshots where available.
- Keep the Reports section hidden until real reports are available.
- Do not invent metrics, testimonials, employers, outcomes, or project claims.
- Prefer original visual design. If an external template or asset is adopted, record its source and attribution clearly.

## Brand Commitments

- Name: Lintao (Andy) Zhang.
- Academic identity: Computer and Information Science student at The Ohio State University with a Business minor.
- Existing photo, resume, project assets, GitHub, LinkedIn, email, and live AI Customer Support demo are approved portfolio materials.
- The visual result should feel authored and specific to Andy's work, not like an unmodified template or generic AI-generated landing page.

## Product Principles

1. Show the work before explaining the work.
2. Make technical range legible through specific evidence and outcomes.
3. Connect engineering, data, AI, and operations into one coherent story.
4. Use restraint: every visual effect must improve wayfinding or recall.
5. Keep the page honest, accessible, responsive, and easy to maintain.

## Accessibility & Inclusion

The site should preserve semantic HTML, meaningful image alt text, visible keyboard focus, adequate contrast, touch-friendly targets, responsive layouts without horizontal scrolling, and reduced-motion behavior.
